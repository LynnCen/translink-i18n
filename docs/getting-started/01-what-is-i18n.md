# 什么是国际化？

> **让你的应用「说」多种语言**

---

## 🤔 一个简单的问题

假设你开发了一个网站，上面有一个按钮：

```html
<button>登录</button>
```

现在，你的老板说：「我们要进军海外市场，网站需要支持英文。」

你会怎么做？

### 方案 A：简单粗暴

```html
<!-- 中文版 -->
<button>登录</button>

<!-- 英文版 -->
<button>Login</button>
```

创建两套页面？❌ 维护噩梦！

### 方案 B：条件判断

```javascript
<button>
  {language === 'zh-CN' ? '登录' : 'Login'}
</button>
```

到处写三元表达式？❌ 代码混乱！

### 方案 C：国际化（i18n）

```javascript
<button>{t('login')}</button>
```

使用翻译函数！✅ **这就是国际化！**

---

## 📖 什么是 i18n？

**i18n** 是 **Internationalization** 的缩写（因为 i 和 n 之间有 18 个字母）。

> **国际化 = 让应用能够适应不同语言和地区**

核心思想很简单：

```
1. 把文本从代码中「抽离」出来
2. 根据用户语言「动态加载」对应翻译
```

### 工作原理

```
代码                    翻译文件                    显示结果
┌──────────────┐       ┌──────────────┐           ┌──────────────┐
│ t('login')   │   +   │ zh-CN:       │    →     │ 登录         │
│              │       │   login:登录  │           │              │
└──────────────┘       │ en-US:       │           └──────────────┘
                       │   login:Login │
                       └──────────────┘
```

## 🌍 为什么需要国际化？

### 1. 全球化市场

- 全球互联网用户超过 50 亿
- 只有约 25% 使用英语
- 本地化可以提升 70%+ 的用户体验

### 2. 用户体验

```
用户看到母语 → 信任感 ↑ → 转化率 ↑
用户看到外语 → 困惑 → 流失 ↑
```

### 3. 合规要求

某些地区有语言法规：
- 欧盟：GDPR 要求隐私政策用当地语言
- 加拿大：某些场景必须同时提供英法双语

---

## 📊 i18n vs L10n

你可能还会听到 **L10n**（Localization，本地化）：

| 概念 | 含义 | 例子 |
|-----|------|------|
| i18n（国际化） | 让应用**能够**支持多语言 | 使用 `t()` 函数 |
| L10n（本地化） | **实际**翻译成某种语言 | 把 "Login" 翻译成 "登录" |

简单说：
- **i18n** 是「做准备」
- **L10n** 是「实际翻译」

## 🔧 国际化涉及什么？

### 不只是文本翻译！

```javascript
// 1. 文本翻译
t('welcome')  // 欢迎 → Welcome

// 2. 日期格式
formatDate(date)  // 2024年1月1日 → January 1, 2024

// 3. 数字格式
formatNumber(1000)  // 1,000 → 1.000（德国）

// 4. 货币格式
formatCurrency(100)  // ¥100 → $100

// 5. 排序规则
sort(['张三', '李四'])  // 中文按拼音？按笔画？

// 6. 文字方向
// 中文：从左到右 →
// 阿拉伯语：从右到左 ←
```

### 本教程聚焦

本教程主要聚焦于**文本翻译**，这是最常见也是最核心的国际化需求。
